# 跨学科创新发现流程

用于主动发现创新点、探索指定学科交叉和评审跨域候选。以下是可执行的探索启发式，不是能保证原创、提高发现成功率或证明机制成立的方法。

## 1. 把目标问题转成关系描述

先记录具体需求与基线，再写一份去除专业名称的目标描述：

- 对象及尺度：有哪些实体、状态、层级和交互？
- 输入与观测：能知道什么、不能知道什么，观测成本多高？
- 可操作部分：能改规则、表示、测量、采样、交互顺序还是系统结构？
- 动态关系：反馈、延迟、竞争、组合、传播、记忆、不可逆性等实际存在什么？
- 目标与失败：想保留什么，想降低什么；哪些失败可区分？
- 约束：哪些是用户或物理/逻辑硬约束，哪些是惯例，哪些尚不清楚？

例如将“改善文档检索”进一步限定为“有限观察下，从可能使用不同表述的对象中选择有用对象；逐项比较有成本，且错误匹配和遗漏的代价不同”。这只改变搜索视角，不证明与任何特定源领域同构。

抽象到能发现关系即可。过度抽象成“所有问题都是信息处理”会失去辨别力，应返回具体瓶颈。

## 2. 有意拉开来源，但按机制取样

采用三个相对距离层级，不给虚假的统一距离数值：

| 层级 | 选择依据 | 在本次探索中的作用 |
| --- | --- | --- |
| 近 | 共享问题、工具或惯常研究群体 | 提供合理参照，识别是否仅在改名 |
| 中 | 对象不同，但常用方法或形式结构接近 | 容易建立较明确的迁移 |
| 远 | 惯常问题、实践或知识表达方式差异明显 | 寻找新的表示、规则、关系或问题重构 |

同一对学科对不同任务可能有不同距离。不要把“计算机+神经科学”“优化+经济学”等常见连接自动列为新颖远域成果。

通常先看 4–6 个来源，跨多个关系类型，其中留出至少两个明显远域尝试；用户要快速少量建议时缩减。这是防止只在熟悉领域内搜索的取样安排，不是必须交付的数量，找不到内容就不凑。

来源可以来自自然现象、工程规则、社会组织、人文研究、艺术形式或实践技艺。若所有候选最后都是相同的“加反馈”“加权平均”或“自适应阈值”，返回目标描述，改换关系类型或干预位置，不能把换学科名称算多样性。

需要来源提示时读 [mechanism-atlas.md](mechanism-atlas.md)。不要每次套用同一组熟悉的比喻。用户已指定两个远域时，先认真探索这对连接；若它不成立，指出断点并尝试一次有说明的改写或中介领域，而不是立即转回熟悉的机器学习方案。

## 3. 为连接建立可检查的映射

每个有希望的连接用以下内容回答“究竟借什么”：

| 项目 | 需要给出的内容 |
| --- | --- |
| 来源规则 | 在源领域中的真实规则、模型、实践或观察；注明可核查来源或“待核查” |
| 迁移类型 | 数学结构、算法操作、表示方法、组织协议、测量/评价设计，或尚待形式化的启发 |
| 实体对应 | 源与目标中分别由什么扮演什么角色；不强迫每个元素都有对应物 |
| 关系对应 | 哪个关键关系、约束或操作被保留，如何保留 |
| 必要前提 | 要让这一步迁移有意义，目标系统必须满足哪些条件 |
| 失配与不能迁移部分 | 至少一个重要不对应之处，以及它是否破坏关键关系 |
| 实际改动 | 一个目标系统中可定位的步骤、变量、约束、交互或表示改变 |
| 区分性预测 | 与近域参照相比，在什么条件下预期出现什么不同，为什么 |

区分三种连接：

- **形式上对应**：写出保留的关系或算子及条件；需要证明的地方明确未证明，不用“同构”代替推导。
- **启发式迁移**：源领域提供一项具体操作，目标效果仍需实验；不给它套用源领域的证明。
- **解释或表达类比**：只帮助理解，尚未改变操作或可检验预测。可以保留为灵感，但不能与前两类并列为已可行的创新方案。

来自艺术、历史或哲学的结构与实践可以启发新表示、问题定义或交互规则。它不必是自然定律；说明借用的是哪一种知识，以及目标实验评估的到底是效用、认知效果还是物理机制。

## 4. 审查“不可能”究竟指什么

在生成阶段允许陌生、反直觉和不成熟的连接。随后逐项检查：

- 源与目标的时间、空间、单位或信息尺度是否兼容？
- 规则是否依赖目标系统没有的状态、观测、控制权、长期历史或交互反馈？
- 是否把有意图的行为当成固定物理过程，或把开放、变化的系统当成封闭稳态？
- 是否误用了守恒、独立性、线性、平衡、可逆性等前提？
- 所谓矛盾是两项目标间尚未解决的权衡，还是已声明条件下真正不能同时成立？

将断点分为：

1. **可质疑的惯例**：写出放松后会变什么，保留目标硬约束。
2. **待建立的前提**：写出先要验证或获得的能力，作为探索方向。
3. **破坏核心关系的失配**：否定当前映射，尝试一次有内容的重构；仍不成立就记录未找到有效连接。

可用一个中介领域建立“源 → 中介 → 目标”，但要逐段写明迁移内容与新增假设。两段各自看起来合理，不代表端到端联系已经成立；增加中介不应仅为延长术语链。

## 5. 去掉学科包装，核查真正差异

将每个入选方案再写成不含源学科名词的一两句操作描述，再问：

- 这是否已经是目标领域中的缓存、迟滞、分层、正则化、调度、组合约束等已有做法？
- 若已经存在，差异究竟是适用场景、具体规则、条件边界、新测量，还是没有差异？
- 哪个可观察结果会使“这个远域联系有额外价值”的主张不成立？

允许联网时，对入选方向分三路核查：

1. 源机制的原始表述和限制。
2. 去术语后最接近的目标领域方法，含不同名称。
3. 两个领域的交叉迁移、相同关系的既有应用及失败条件。

优先原始论文、官方方法资料和实际实现；对人文、艺术和技艺来源使用相应的一手作品、规则或可靠研究资料。不能只搜索“A 学科 + B 学科”就认定空白。没有网络时仍可生成并写出待核查路径，不编造罕见理论名称、来源或公式。

## 6. 设计能判断这条联系的最小实验

先验证最脆弱的一步，而非直接把整个系统堆起来。按候选需要选择：

- 原基线与目标领域最接近的合理方法。
- 加入被迁移规则的方案，保持关键信息、容量和预算可比。
- 去掉或替换被迁移关系，检验收益是否来自它。
- 选择关键前提成立与不成立的场景，观察预期差异是否随之改变。

只比“加规则”与“不加规则”可能只能证明某种一般操作有用，无法支持这个特殊来源的解释。需要时加一个目标领域常规做法作参照。若跨域方案与既有方法实际相同，就把问题改为新场景、边界或机制理解的验证。

提出至少一条区别于“整体更好”的具体预测，例如：仅在约束冲突加重时改善、在信息延迟超过某条件后失效、源关系被打乱后优势消失。预测内容应由该映射推出，不能事后随结果改写。

按 [validation-design.md](validation-design.md) 校验对照和测量；按 [output-templates.md](output-templates.md) 输出可裁剪的跨域卡片。

## 7. 收敛时保留可检验的探索空间

可分别推荐一个当前资源下最值得检验的方向和一个远域探索方向。后者写清前提缺口与第一步检验；不要只因短期分数低就删掉，也不要因听起来大胆就优先。

一个连接反复无法形成具体操作或区分性预测时，停止修补并换关系来源。完成少量候选与关键核查后收敛，不无限枚举学科。用户希望继续深挖时，再扩展来源或做下一轮实验反馈。

最终展示目标抽象、少量候选、推荐映射与验证即可。内部尝试的所有交叉组合无需倾倒给用户，但重要否定结果和未解决断点应说明。
